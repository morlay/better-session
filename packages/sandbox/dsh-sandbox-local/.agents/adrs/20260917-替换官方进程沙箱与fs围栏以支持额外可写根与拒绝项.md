# 替换官方进程沙箱与 fs 围栏以支持额外可写根与拒绝项

状态：已采纳

`@morlay/dsh-sandbox-local` 用自有实现替换官方 `ctx.sandbox`（进程沙箱）与
`ctx.fs`（文件系统围栏）：进程沙箱继承官方 `LocalSandboxProvider` 并在其
`confine` 结果上追加规则，fs 侧继承官方 `LocalFileSystem` 并自实现围栏判定。
规则来自部署级 Config（`access` 条目：`rw <path>` / `r- <path>` / `-- <pattern>`），因为上游 `SandboxPolicy` 只有
`mode` / `workspaceRoot`，而 `confine(argv, policy)` 是接口契约、不能扩容。
字段与语法见 [README](../../README.md)。

## 考虑过的选项

- **只改官方行的 config**（`sandbox` / `sandbox-policy`）：`sandbox-policy` 的
  `mode` / `workspaceRoot` 表达不出「追加可写根」与「拒绝某个子路径」；上游把
  `writableRoots` 硬编码为 `[工作区, /tmp, os.tmpdir()]`。
- **用官方 `sandbox-local.runnerCommand` 注入 profile 参数**：它会断言 full
  enforcement 并跳过平台探测，`denialSignatures` 退化为固定两条，而且官方只承诺
  「追加 bwrap 兼容的 profile 参数」——Seatbelt / Landlock / Windows 的表达能力
  都失去。
- **改上游 `profiles.ts`**：触碰「上游代码不可修改」红线（本地 patch 是唯一例外，
  但会让每次上游同步都要重新评估，且规则本身是用户配置而非上游缺陷）。
- **隔离域里注册第二个 provider**（`ctx.isolate`）：同一 scope 重复注册同名服务
  本来就会 fail loud；用隔离域换实现需要额外的 loader 语义与卸载时序，收益只是
  避免禁用官方行一次 `disabled: true`。

## 后果

- **跨平台表达能力不对称，加载期告警而非静默失效**：Seatbelt 能表达全部三类条目
  （后置 SBPL 规则覆盖官方先置的 allow，已用真实 `sandbox-exec` 验证）；bwrap 把
  `r-` 与 `--` 都表达成只读挂载（`--ro-bind-try`，`--` 因此退化为「只拒写入」），
  Landlock 的 allow-list 无法减除子路径，Windows ACL runner 的 argv 没有承载额外
  grant 的入口。`ctx.fs` 侧在所有平台语义一致，因此降级只影响 bash 等子进程。
- **`ctx.fs` 侧仍是策略检查**，与它替换掉的官方 `fs-sandbox` 同一威胁模型
  （受信代码 + 模型可控路径）；内核级隔离仍归 `ctx.sandbox`。
- **规则与自定义 runner 互斥**：无法识别的 runner argv 会让规则在 `confine` 抛错——
  宁可失败也不让规则静默失效。
- **`rw` 条目不接受 glob**：可写根没有「通配」语义，含通配符的条目在编译期报错。
- 装配要求官方 `sandbox` / `fs-sandbox` 行保持 `disabled: true`；本包 patch 里的
  装配守卫测试会在上游改名/移动这些行时失败（提示同步），而不是让替换静默失效。
