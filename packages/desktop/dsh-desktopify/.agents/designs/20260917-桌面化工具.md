# 桌面化工具（dsh-desktopify 的实现与取舍）

状态：已实现（`dev` / `bundle` 两条路径可用，见 [README](../../README.md) 的命令表）
范围：`packages/desktop/dsh-desktopify/` 的实现机制——工具形态、壳与 host、依赖闭包与种子、运行时语义。
约束：壳复用上游 `vendor/deepseek-harness/apps/desktop` 的形态与产物；host 以上游 `apps/desktop-host/src/*` 为源（两处本地适配，其余相对引用，由 `tsdown` 内联），不改 `vendor/**`；工具内不写死任何 app 路径或名字（一律由 node 解析）。

## 事实基线

### 工具形态

源码与 CLI 全 TS。开发形态 `bin` 直指 `src/cli/index.ts`（Node 原生类型剥离直接执行）；
`exports` / `bin` / `main` 由 `tsdown.config.ts` 的 `exports` 选项在构建期收敛进 package.json——开发形态指
`src/*.ts`，发布形态经 `publishConfig` 指 `dist/*`，对外只有 bin 一个入口。

### 壳

Electron 主进程（`dsh-app://` 自定义协议 + host 子进程守护），复用上游 `host-process.ts`
（纯 node 实现，IPC-only 协议 `DESKTOP_HOST_PROTOCOL_VERSION = 4`，stdio `['ignore','pipe','pipe','ipc']`：
`ready {url, injections}` / `fatal` / `shutdown` → `shutdown-complete` /
`update-tasks {requestId, action}` → `{requestId, active, error?}`）；窗口无标题栏（macOS 隐藏标题栏保留交通灯，Windows 经
`titleBarOverlay` 保留系统窗口控制按钮，其余平台无边框），退出（红叉 / Cmd+Q / 菜单）先经确认框，
确认后才停止后端并退出。产物 `dist/index.mjs` + `dist/preload-app.cjs`（sandboxed preload 必须是 CJS）。

文档与转发复用上游三个纯 node helper（同目录 `src/web-document.ts`）：`serveWebDocument` 从本地
`@deepseek-ai/dsh-web-frontend/dist` 提供 `/`、`/index.html`、`/assets/*`、`/favicon.svg`、
`/manifest.webmanifest`，并在 index 注入 `__DSH_BOOT_READY__` gate；`authenticateWebHost` 用
`fetch(url, {redirect:'manual'})` 换 Host 的认证 cookie；`forwardWebRequest` 把其余路径转发到 Host
（带 cookie，`ws://127.0.0.1/*` 经 `onBeforeSendHeaders` 重写 origin / cookie）。渲染半经 preload 的
`dshDesktopBoot.{ready, failed}` 拿 `{injections, streamBaseUrl}`；native 目录选择是 Electron 侧实现
（`src/directory-picker.ts`，复制上游同名文件，不依赖上游私有包）。

### 启动链

- **顺序**：先 `startHost()`（拿到 `ready` 的 `url` + `injections` 与认证 cookie）再 `loadURL('dsh-app://app/')`；
  反了页面拿 503 且不自动重载。
- **渲染侧 gate**：前端在 `__DSH_BOOT_READY__` 上等 boot IPC，拿到 `{injections, streamBaseUrl}` 并应用注入表
  后才跑 client entry。
- **DSH_HOME 显式设置**：host 经 shell 注入启动会继承用户 shell 里残留的 `DSH_HOME` export，壳启动 host 时
  显式传 `DSH_HOME`（`src/index.ts`）。
- **preload 暴露面**：只在 `dsh-app://app` 上暴露 `dshDesktopBoot.{ready, failed}` 与
  `__DSH_DIRECTORY_PICKER__`（`src/preload-app.ts`）。

### 打包

electron-builder 经 Node API 在 `src/cli/electron-builder.ts` 内配置（无独立配置文件）。壳以最小 app 目录
（`dist/` + 入口 manifest，版本取工作区版本）打包，工具自身的构建依赖不进 app；`--dir` 产出未打包的
应用目录，不签名、不 notarize。

### 后端（`@morlay/dsh-desktop-host` 的搬运）

后端变体是**独立包** [`@morlay/dsh-desktop-host`](../../dsh-desktop-host/README.md)（`packages/desktop/dsh-desktop-host/`），
工具以 `dependencies: workspace:^` 引用它，不再把载荷塞在工具产物里：

- `src/index.ts` 是上游 `apps/desktop-host/src/index.ts` 的逐行复制，三处本地适配——Office 组合指向本地差异版、
  `update-tasks` 直接引用上游、`process.disconnect` 可选调用（上游那个 `main` 没有导出，入口无法靠 re-export 复用）；
  `src/office.ts` 是唯一功能差异：只装载 workspace-dependencies、不装载 officeSkills。其余上游零件
  （`update-tasks.ts`、`workspace-dependencies.ts`、`primary-runtime.ts`）不复制，按相对路径从
  `vendor/deepseek-harness/apps/desktop-host/src/` 引用，由 `tsdown` 构建时内联进 `lib/index.js`，所以发布包不依赖
  源码路径。
- **自己的 manifest 只声明这份代码真正用到的依赖**（`dsh`、`dsh-app-boot`、`dsh-home-paths`，`cordis` 为 peer）：
  上游那份 app manifest 里的组合依赖（`dsh-skill-office`、`dsh-agent`、`dsh-jobs`、`dsh-tools` …）属于部署的官方
  闭包，由 profile 面提供，不由载荷声明——照抄它会要求部署去装一个本变体根本不挂的技能包。
- 工具按 `dependencies` 解析到载荷目录（`desktopHost()`：`import.meta.resolve` 从工具出发，只可能落到自己的依赖），
  部署里落位在 `node_modules/@morlay/dsh-desktop-host`，闭包装配时强制覆盖该位置
  （`materializeDesktopHost`），所以工作区 / vendor 里的上游同名包永远不会被选中。Host argv 由壳给出：
  `entry, runtimeDir, projectDir, primaryRuntime, profileResolution, [pnpm, nodeBin]`。

### 随包运行时载荷

`dev` 与 `bundle` 都在 `<buildRoot>/runtime` 下准备随包载荷（`cli/prepare-runtime.ts`、`cli/office-assets.ts`、
`cli/bundle.ts`）：

- **`node/`**：按 Node 官方 `SHASUMS256.txt` 校验下载的随包 Node；`bin/` 是指向它的相对链接（Windows 下
  复制 `node.exe`），作为 pnpm 子进程 `PATH` 的前置目录（host argv[7]）。
- **`pnpm/bin/pnpm.mjs`**：pnpm 入口，壳作为 host argv[6] 交给 `profileContext.packageManager`。pnpm 12 的 npm
  包只是 wrapper：入口会 spawn 同包装的 `@pnpm/exe.<platform>-<arch>` 原生二进制（约 35 MiB），所以载荷按入口
  实际加载的闭包复制 wrapper（约 3.5 MiB），并把平台包放进 `<runtime>/pnpm/node_modules/`；两处复制都要
  dereference（否则符号链接指向仓库 store，打包后断链）。准备完立即用随包 node 跑 `pnpm.mjs --version` 与
  manifest 版本比对。
- **`versions.json`**：`{schemaVersion: 1, node, pnpm}`（纯增量字段，形状与上游桌面一致）。
- **`primary-runtime/`**（当前为空）、**`appconfig.json`**。**不带 `office-skills/`**：那份资源唯一的读者是上游
  命令式装载的 `officeSkills`，本变体不挂它（见「后端」），随包只会让打包多一个解析不到的
  `@deepseek-ai/dsh-skill-office` 硬依赖。

跨平台打包被拒绝：载荷只含构建主机平台的 `@pnpm/exe` 二进制，`DSH_DESKTOP_TARGET_PLATFORM` /
`DSH_DESKTOP_TARGET_ARCH` 指向别的平台时在任何写入之前就失败
（`desktop runtime: bundled pnpm carries the <host> native binary, which cannot serve <target>`）。

### 官方依赖内部维护与闭包装配

`@deepseek-ai/*` 依赖清单（dsh、cordis-plugin-group 及约 20 个 peer 包）由工具内部维护
（`src/official.ts`），app 只声明自己的依赖、`dsh.version` 与 bundles。包位置一律由 node 解析
（`src/cli/official-deps.ts`）：app 工作区优先、工具自身安装兜底，不写死 `workspace:`；**后端载荷是唯一
例外**——它由工具自己的依赖（`@morlay/dsh-desktop-host`）解析，因为变体才是要跑的后端。

打包时官方依赖分两条路进闭包：

- **registry 面交给 pnpm**：按工作区已解析版本写进 `deploy/package.json` 再 `pnpm install`（工作区没装的
  `@deepseek-ai/dsh*` 按 app 的 `dsh.version` 钉版本；独立版本线如 `cordis-plugin-group` 1.x 不猜版本），
  文件集语义由 npm/pnpm 负责（`files` 不会裁掉 `main` / `bin` / README / LICENSE）；
- **本地源码包与工具依赖的后端载荷** 仍由闭包复制补齐（它们带 `workspace:` 依赖，在部署项目里解析不了）。

装之前部署项目先继承工作区的安装设置（`minimumReleaseAge` 等，`pnpm deploy` 只带走 `allowBuilds` /
`patchedDependencies` / `overrides`）。工作区的清单与 lockfile 始终只读。

### 运行时与 profile 分离

- **runtime**（`seed/runtime`）：deploy 闭包的副本（`package.json` + `node_modules`，保留 pnpm 虚拟存储与相对
  链接），随包留在应用的只读 resources 里。它同时是 host 的 dsh 安装（解析锚点 = Host argv[2] 的 runtimeDir）、
  前端静态资源（`@deepseek-ai/dsh-web-frontend/dist`）与桌面 preset 的物化目标（`config/agent-presets`），
  也是 profile `overrides` 指向的包源；它不再被种进 `DSH_HOME`。
- **profile**（`seed/profiles/desktop`）：只带 app 自己声明的 bundle。manifest 里这些包是
  `file:./vendor/<name>`（`vendor/` 是从 runtime 闭包 deref 复制出来的源），外加 app 白名单文件与
  `pnpm-workspace.yaml`（`nodeLinker: hoisted`、`autoInstallPeers: false`、从工作区继承的 `allowBuilds`）。
  官方 bundle 与 dsh 不进 profile，由 runtime 提供；manifest 也不再带 app 的 `dsh.version` / `desktop` /
  `dev`（那些属于打包输入）。
- **安装**：壳在种出 profile 后，先按种子写的 `desktop-runtime-packages.json` 把 `overrides`
  （`"<dep>": "link:<runtime>/<package path>"`）写进 `pnpm-workspace.yaml`，再用随包 node 跑随包 pnpm 的
  `install --prod --ignore-scripts --offline`。报告覆盖 profile 本地包的**每一条**依赖（普通范围如
  `zod@^4.4.3` 与 `workspace:` 协议都算）；漏掉普通依赖时 pnpm 会回 registry 解析范围，离线只能查 metadata
  镜像并失败（打包产物首次启动报 `profile install exited with 1` 就是这个原因）。peer / optional 找不到就跳过
  （`autoInstallPeers: false`），普通依赖找不到则打包直接失败。依赖全部由 `file:` 源与 `link:` 覆盖满足，
  安装不访问 registry，profile 里的包也与 runtime 共享同一份实例。
- **peer 闭包**：`pnpm deploy --prod` 不装 peerDependencies，desktop-host boot 依赖的 `@deepseek-ai/*` peer
  包由工具注入为具体版本依赖（`dsh.version` 锚定 dsh，其余取已解析版本；desktop-host 以 `link:` 注入），
  随 deploy 复制进闭包。

### bundles 自动合并

官方 bundles（`@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app`）+ app 的 `dsh.profile.bundles`
自动合并进 dev 项目与种子 profile。

### 桌面 preset 物化

桌面宿主把 `agent-presets.roots` 固定为 dsh 包内的 `config/agent-presets`（`system` root），bundle patch 里
配的 roots 在桌面形态下不生效，registry 版 dsh 包内该目录也是空的。工具装配 profile 时把 preset 目录物化到
该挂载点，两条来源：

- **随包声明**：profile bundle 用上游同名字段 `dsh.configTrees`（`mount: config/agent-presets`、`path`
  相对包根）声明自己的 preset 目录，工具自动发现（`@morlay/dsh-preset` 即声明 `dist/presets`）；
- **app 显式**：`dsh.desktop.agentPresets` 列出 app 自带或要覆盖的目录（包名 + 子路径，如
  `@scope/pkg/presets`），最后应用。

dev 项目里 dsh 包因此以真实副本装入——工作区链接指向只读的上游树，挂载点写不进去。

### 运行流程

- **dev**：链接工作区依赖闭包 + 后端载荷（`@morlay/dsh-desktop-host`）到临时项目（dsh 包以真实副本装入，见「桌面 preset 物化」），
  host 用系统 node 直载工作区 TS 源码——仅当工作区装有 tsx 时才加 `--import=tsx/esm`（否则不注入 loader），
  profile 解析模式（Host argv[5]，只有 `runtime` 才按 runtime 解析）给 `link`；`--web` 则准备 `web` profile 后启动
  `dsh web`。
- **bundle**：`pnpm deploy --prod` 导出 app 闭包（工作区清单与 lockfile 只读）→ 部署项目继承工作区安装设置；
  官方 registry 面由 pnpm 装进部署项目，本地源码包与后端载荷由闭包复制补齐 → 种子（`seed/runtime` +
  `seed/profiles/desktop` + `.seed-hash`）→ 随包 pnpm 与运行时载荷 → 下载校验随包 Node 二进制 →
  electron-builder 静态打包，profile 解析用 `runtime`。
  指纹覆盖 app 工作区白名单、根 lockfile、闭包内每个本地源码包的产物内容、每个安装产物的文件清单，以及种子自己
  生成的文件（runtime manifest、profile manifest / pnpm 设置 / `desktop-runtime-packages.json`、vendor 的包路径
  清单）——指纹变化时壳在启动时替换 profile，并重新安装它（本地源码依赖版本号不变、内容也可能变；安装产物版本
  固定，但工具选哪些文件进闭包会变）。闭包内 `@morlay/*` 的 exports 切到 publishConfig 的 dist 产物（打包环境
  没有 tsx）。
- **primaryRuntime**：Host argv[4] 指向 bundled 依赖载荷，只在 `load_workspace_dependencies` 工具被调用时
  惰性安装。壳把它固定为 `<runtime 根>/primary-runtime`（dev 经 `DSH_DESKTOP_PRIMARY_RUNTIME_DIR`，打包形态取
  `process.resourcesPath/runtime/primary-runtime`）；完整 payload（Python / numpy / pandas / pnpm）未随包，缺了
  不阻塞启动，见[债务 20260918-桌面未随包primary-runtime载荷](../../../../../.agents/debts/20260918-桌面未随包primary-runtime载荷.md)。

### 运行时语义

- **XDG 路径**：`dshHome: xdg`（默认）→ `xdg.DataHome/<name>`（macOS `~/Library/Application Support`、
  Linux `$XDG_DATA_HOME`）；`DSH_APP_DSH_HOME` 可覆盖（开发 / 测试）。
- **shell 注入**：Unix 上 host 经 `$SHELL -c 'source ~/.bashrc; exec …'` 启动（bash/zsh），继承用户终端环境
  （API key 等）；`exec` 保持同进程，进程组终止语义不受影响。
- **morlay 插件适配**：桌面形态不禁用 webserver——Host 跑完整 Web 应用，`/api/session-editor`
  在桌面下经 `dsh-app://app/api/*` 认证转发命中 Host 侧由 `connection.fetch` 注册的同名路由（web 模式仍走
  `webServer`）；客户端按 `__DSH_TRANSPORT__.ownsHost` 加 `/api` 前缀。注册该路由时 connection 可能已
  provide（`internal/service` 事件已错过），所以监听该事件并立即检查一次
  （`packages/session/ui-conversation-message-actions/src/index.ts`）。
- **未覆盖面**：Electron 主进程 / preload（导入即触发 `app.whenReady()` 等副作用）与 `cli/{bundle,dev}.ts`
  的私有逻辑没有自动化测试——要整套 Electron mock 面；纯 node 的协议、文档 / 认证 / 转发按接缝测
  （判据与未覆盖清单见 [本包如何验证](../standards/how-to-verify.md)）。
- **启动即静默退出**：Electron 的单实例锁落在 userData 目录里；进程被强杀或 PID 被复用后残留的
  `SingletonLock` 会让新实例直接退出（无输出、退出码 0）。清掉 `<userData>/Singleton*`
  （macOS `~/Library/Application Support/<app id>/`）即可恢复；同一个 app id 同时只允许一个实例。

## 取舍

- **官方依赖的 registry 面交 pnpm 而非自己复制**：文件集语义（`files` 不裁 `main` / `bin` / README /
  LICENSE）由包管理器负责；自建复制要跟住上游每个包的 manifest。
- **runtime 与 profile 分离、profile 交给 pnpm 装**：profile 必须是 pnpm 能接管的真项目，Web 插件页的安装 /
  卸载 / 启停才能在打包产物里工作——把 deploy 闭包直接当 profile 时，pnpm 的依赖图与磁盘不一致（手工复制进闭包
  的包不在图里），任何包操作都会把那些包 prune 掉；分离后 profile 只声明 app 自己的 bundle，官方包与 dsh 由
  runtime 提供，这也是上游桌面的形态（profile 只装外部插件、core 由签名 runtime 提供）。
- **`overrides` 用 `link:` 指回 runtime，而不是把包复制进 profile**：profile 里这些包的 `@deepseek-ai/*`
  依赖因此共享 runtime 的同一份实例（cordis 尤其），也不再多占一份闭包；代价是 `pnpm-workspace.yaml` 的
  `overrides` 由壳在种出 profile 时写入（种子里的设置保持静态），空列表时不碰文件，以免覆盖手写内容。
- **随包 pnpm 而不是内置包管理器实现**：与上游桌面同源——Electron 的 Node 模式 + 随包 pnpm 作为
  `profileContext.packageManager`，插件页的包操作与官方桌面走同一条路。代价是载荷要带平台原生二进制
  （见「随包运行时载荷」），跨平台打包因此被拒绝。`allowBuilds` 里保留 `pnpm: true`：pnpm 包的 install 脚本
  正是把包内 shim 重链接到那份原生二进制的那一步。
- **host 变体按相对路径引用上游源码，而不是复制整份**：独立包 `@morlay/dsh-desktop-host` 只有入口 `index.ts` 与
  `office.ts`（唯一功能差异），`update-tasks.ts` / `workspace-dependencies.ts` / `primary-runtime.ts` 直接引用
  `vendor/deepseek-harness/apps/desktop-host/src/`，由 `tsdown` 构建时内联——上游升级只需 diff 这两个文件，发布包
  又不依赖源码路径。入口仍必须整份复制：上游的 `main` 没有导出，无法靠 re-export 复用。
- **后端变体独立成包，而不是塞进工具产物**：工具只管打包，载荷的身份（`@morlay/dsh-desktop-host`）、入口路径
  （`lib/index.js`）与依赖清单（只声明它真正用到的）都归那个包；从上游 app manifest 抄依赖会把变体早已移除的
  `dsh-skill-office` 之类重新变成部署的硬要求（2026-09-18 非 workspace 安装即因此报
  `@deepseek-ai/dsh-skill-office cannot be resolved`）。回归由该包的 `manifest.spec.ts` 守住：清单与产物互相覆盖。
- **dev 项目里 dsh 包用真实副本而非工作区链接**：桌面 preset 的挂载点在 dsh 包目录里，链接指向只读的上游树
  写不进去。
- **文档、认证与转发复制上游实现而非自造**：`serveWebDocument` / `authenticateWebHost` /
  `forwardWebRequest` 与 `directory-picker.ts` 是纯 node / 纯 Electron 面，逐行复制上游、按接缝测
  （转发路径与 cookie、303 + set-cookie 才算认证、index 的 boot gate），升级时按 diff 跟住。
- **壳产物由 `pnpm build` 生成、dev / bundle 只校验不重建**：壳构建是独立一步（`dist/index.mjs` +
  preload），工具不替上游壳管构建；源码形态下产物比源码旧只打印警告。
- **工具内不写死 app 路径与包名**：包位置一律 node 解析（工作区优先、工具安装兜底），换工作区不改代码。
