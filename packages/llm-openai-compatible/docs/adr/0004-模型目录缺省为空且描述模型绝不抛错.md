# 0004-模型目录缺省为空且描述模型绝不抛错

`models` 缺省 = 服务**空目录**：`listModels` 返回空，未列出的 id 原样透传
（`resolveModel` 返回基础信息 + `defaultContextWindow` / `defaultMaxTokens`）。
模型声明 `reasoningEfforts` 后选器公开 `efforts` + `defaultEffort`（=
`profile.reasoning`，须在模型能力内，否则视为无默认值——**描述模型时绝不
抛错**）；请求级 `options.reasoningEffort` 不在模型能力内 → 网络 I/O 前抛
`LlmError('UNSUPPORTED_REASONING_EFFORT')`。

## 考虑过的选项

- **模型 discovery**（端点询问 `GET /models`）：暂缓（YAGNI）——需要时
  手写 `models`。
- **描述模型时抛错**（配置了模型不支持的档位）：配置页面无法编辑——错误
  推迟到请求执行处（同一错误码），配置仍可保存。

## 后果

- 未列出的模型 id 原样透传——空目录下任何 id 都可用，能力信息用默认值。
- `profile.reasoning` 配了模型不支持的档位 → 请求执行处失败，配置页面仍
  可编辑。
