# 压缩事务在重写时补回

状态：已采纳

压缩（`compaction/start` → `compaction/summary` → `user/message` checkpoint（`surfaceOp: replace`）
→ `compaction/end`）是**已生效的历史**：它把被摘要遮蔽的消息从模型上下文里拿掉，压缩点之后
的对话都建立在摘要之上。就地编辑 / 撤回的 rewind 边界只按轮次找（`precedingContentIndex` 取
「前一个内容轮」），于是「压缩后的第一条用户消息」的边界落在**压缩之前**的 `turn/end`——压缩
四件套随目标轮一起被截断。后果有两层：上下文退回未压缩形态（摘要失效），以及日志里留下
未闭合的 `compaction/start`，上游据此判定压缩仍在进行，之后再也压不了。

**决定**

rewind 仍然只截断到 `turn/end` / `user/message` 边界（不改 provider 的边界契约）；**整段落在
`[keepFrom, 目标事件)` 区间的完整压缩事务，在重写时补回**——重排为 standalone 形态
（`compaction/start` 的 `turn: null`）的连续 seq，`surfaceOp` 的 range、metering 事件的
`shadowedRange` / `shadowedSeqs` / `sourceEventSeqs` 同步重编号，保证 metering 事件与相邻 replace
仍成对。补回位置在版本效果之后、手工回合 / 重放输入之前（编排层 `appendSeedSuffix`），
`edit` / `retry` / `reroll` / `recall` 四条路径一致。

**考虑过的选项**

- **把 rewind 边界扩到 `compaction/end`（原地留在保留前缀里）**：前缀会停在未闭合的轮次上，
  需要补一条合成的 `turn/end(interrupted)` 并把重放输入推到下一个轮号；还要扩 provider 的
  边界校验与 [session-rdb ADR 0003](../../../session-rdb/.agents/adrs/0003-rewind绕过handle模型直接截断.md)
  的措辞——语义扰动与契约改动都比收益大，否掉。
- **不补回（原状）**：摘要失效 + 压缩不可再触发，等于把压缩当没发生，否掉。
- **把压缩 checkpoint 当作「内容轮」参与 `closedTurns`**：会改变轮次导航与「可重试轮次」的
  口径（checkpoint 的 `source.kind` 是 `plugin`，不是用户消息），否掉。

**后果**

- 压缩在重写后仍是历史的一部分：重放只重放目标输入，界面上的摘要节点（`CompactionItem`）与
  上下文占用都保持压缩后的形态；`closedTurns` / `retryableTurns` / `editableMessages` 与轮次
  号不受影响（重放仍复用原轮号）。
- 边界类型没有扩：`session-rdb` 的 rewind 仍只接受 `turn/end` / `user/message` 两类边界。
- 未覆盖：`compaction/prune`（工具结果裁剪的 replace）不补回，重放后工具输出会退回原始内容；
  链式压缩（第二个事务遮蔽第一个 checkpoint）按 `moved` 映射处理但暂无专门 fixture。
