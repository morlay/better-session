# 0007-引用的统一解析与渲染转换

状态：已采纳

## 背景

ADR 0006 接管后，这一版引用 wire 已经改过三轮（见文末「形态演进记录」），每一轮的问题都出在同一处：
**把「引用长什么样」和「怎么渲染」绑在了一起**。

- 第一版（XML 资源块 + `<content>` 内联）要输入框结构化、渲染解析自定义 XML、消息膨胀；
- 第二版（`@[label](file:…)`）要自造 chip 渲染；
- 第三版（裸 URI + autolink literal，或渲染前把文本包成 inline code）要么 chip 无法定制（link 节点渲染不可插钩子），
  要么退化成文本层 hack。

## 决策

**解析与渲染分离**：解析产出统一结构的引用，渲染再做转换。

### 1. 解析（一份，host 与 client 共用）

用 markdown 解析器（`mdast-util-from-markdown` + GFM + 我们的 micromark/mdast 扩展）把下列**都合法**的书写
归一到同一个结构：

| 书写                                | 归一                                                                          |
| ----------------------------------- | ----------------------------------------------------------------------------- |
| `skill:xxx` / `@skill:xxx`          | `{ protocol: 'skill', path: 'xxx' }`                                          |
| `@xxx`（手打的裸路径）              | `{ protocol: 'file', path: 'xxx' }`                                           |
| `@xxx#L12-L40`                      | 同上 + `lineStart: 12, lineEnd: 40`                                           |
| `@xxx:1:2`                          | `{ protocol: 'file', path: 'xxx', lineStart: 1, column: 2 }`                  |
| `[label](src/a.ts)`                 | `{ protocol: 'file'（默认）, path: 'src/a.ts', title: 'label' }`              |
| `[label](src/a.ts#L12-L40)`         | 同上 + `lineStart: 12, lineEnd: 40`                                           |
| `[label](https://example.com/a.ts)` | `{ protocol: 'https', origin: 'example.com', path: '/a.ts', title: 'label' }` |
| `@[label](dsh-session:…)`           | `{ protocol: 'dsh-session', path: '…', title: 'label' }`（官方语义原样保留）  |

```ts
export interface Reference {
  readonly protocol: string; // 默认 "file"
  readonly origin?: string;
  readonly path?: string;
  readonly title?: string;
  readonly lineStart?: number;
  readonly lineEnd?: number;
  readonly column?: number;
}
```

- `protocol` **默认 `file`**，所以 http(s) link 走同一套解析（`origin` + `path`），后处理再按 protocol 分流；
- 裸形态（`skill:x` / `@x` / `@x#L12-L40` / `@x:1:2`）由 micromark 扩展在文本构造层认领（词边界起手、已知 scheme
  才吃 `x:y`）：`@` 起手的路径在词边界收尾，**无行号也是 file 引用**，`#L12-L40` / `#L12C3` 这类 fragment 一并吃掉
  （本 UI 没有 cue 人的语义，`@handle` 一律当路径）；
  link / mention 形态由 mdast 转换层认领（label → `title`，`#L12-L40` → 行号）；
- 代码块与 inline code 内的同形文本由解析器天然排除（不在文本上做全局正则替换）；
- 入口：`findReferences(text): readonly ReferenceSpan[]`（`{ start, end, reference }`）。

### 2. 渲染转换（复用官方渲染器，不 fork）

- 官方包 `@deepseek-ai/dsh-client-ui-primitives` 的公共面只有 `MarkdownText` / `CodeBlock` /
  `extractMarkdownPlainText`：`renderBlocks` 等内部件虽然在源码里 `export`，但既不在公共面，官方包在 client 侧
  还是平台 baseline external（模块表按**精确包名**注册，子路径 require 必 miss）——「自组 context + renderBlocks」
  在浏览器里跑不起来；
- 官方唯一的 chip 钩子是 `fileMentions`（只认 inline code）→ 转换规则：**本地引用**（`isLocalReference`：
  非 http/https/mailto）的原文切片换成 inline code——**显示文本省略 protocol**（图标已经表示协议：有 label
  就用 label，否则用 path + 行号 fragment），hover 与 aria-label 是完整引用（`file:src/a.ts#L12-L40`）；
  http(s) / mailto 等外部地址保持 link 原文，官方照常出锚点；
- 判定不靠文本形态：转换同时产出「显示文本 → Reference」映射交给 `fileMentions.resolve`，所以 `code-review`
  这种没有路径特征的 skill 名也能稳定成 chip，而普通 inline code 不会被误判；
- 入口：`ReferenceMarkdown({ text, labels, actions })`（内部 `referenceMentions(actions, 映射)` 接
  `fileMentions`）；点击 file → `openFile(path)`、skill → `openSkill(name)`（owner props，打开右侧栏）——
  **keyed 渲染器也要从 owner props 取这两个动作并透传**，否则点击无反应。

### 3. 其余面沿用已定的三条

1. 输入框保留 raw markdown：pick / 粘贴落裸 URI（`formatReference`），编辑器里不建 chip 节点、不装饰；
2. 提交回单 content block：草稿原文即一个 text 块；
3. host 侧 skill 后注入：`@morlay/dsh-reference-injection` 用**同一个** `findReferences` 找 `protocol === 'skill'`，
   渲染 `<skill_content>` 注入（手写的 `` `skill:x` `` 由 `parseReferenceToken` 再兜一次）。

## 考虑过的选项

| 选项                                            | 代价                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 保持 XML 资源块 + 内容内联                      | 输入框结构化 + 渲染解析 XML + 消息膨胀（第一版已实践）                                            |
| 自造 chip 渲染（切分文本 + 自己的 chip 组件）   | 行内引用会把一行切成多块（`MarkdownText` 是块级），markdown 结构断裂；与官方文件 mention 两套视觉 |
| fork 官方 markdown 渲染器                       | `render.tsx` 685 行 + `CodeBlock`/shiki/katex + CSS module，成为像 ui-chat 那样的长期 fork 面     |
| 打上游 patch 让官方导出渲染内部件               | 与「`vendor/**` 不可改」的红线冲突，且要重建 vendor                                               |
| **统一解析 + 渲染转换到官方 chip 钩子（选定）** | chip 的显示文本要省 protocol（图标已表示协议）；`dsh-session` 等其它 protocol 暂无点击目标        |

## 后果

- **规则只剩一份**：host 与 client 用同一个 `findReferences`（此前 host 有一份独立正则）；
- **chip 语义**：显示省略 protocol 的文本（有 label 用 label，否则 path + 行号范围）、hover 完整引用、
  点击 file/skill 打开右侧栏（点击目标来自 owner props `openFile` / `openSkill`）；没有 `actions` 时照常渲染
  但点击无效果；
  队列行的 chip 没有 owner 动作（点击无效果，视觉一致）；
- **已知取舍**：`[label](uri)` 的 label 只进 `title`，chip 显示的是 token（要显示 label 就得改渲染器）；
  目录 token（`file:src/dir/`）由官方 `classifyLinkPath` 按扩展名判定 → 通用纸张图标而非文件夹图标；
  转换每帧对全文解析一次（与旧实现同量级，官方渲染器的增量缓存不受影响）；
- **历史兼容**：旧消息里的 `@path` 文本由同一解析认领（无行号也成 file chip——本 UI 没有 cue 人，
  `@handle` 不回退成普通文本）；`/name` 仍是普通文本；
- **依赖**：`mdast-util-from-markdown` / `mdast-util-gfm` / `micromark-*` 进 `@morlay/dsh-client-ui-primitives`
  的 `dependencies`（host 面运行时也要解析）；`vendor/**` 未改，未打 patch。

## 形态演进记录

| 版本 | wire 形态                                        | 舍弃原因                                                  |
| ---- | ------------------------------------------------ | --------------------------------------------------------- |
| 一   | `<path>…</path>` + `<content>`（XML 块）         | 输入框结构化 + 渲染要解析 XML + 正文内联膨胀              |
| 二   | `@[label](file:src/a.ts#L12-L40)`                | chip 要自造渲染，与官方 markdown 渲染分叉                 |
| 三   | 裸 URI + autolink literal（或渲染期包反引号）    | link 节点无渲染钩子；包反引号是文本层 hack                |
| 四   | **裸 URI（`file:…` / `skill:…`）+ 统一解析节点** | ——解析与渲染分离，渲染转官方 `fileMentions` chip，零 fork |
