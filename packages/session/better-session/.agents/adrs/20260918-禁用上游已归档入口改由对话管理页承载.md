# 禁用上游已归档入口改由对话管理页承载

状态：已采纳

背景：设置里的「已归档会话」由上游 `@deepseek-ai/dsh-client-ui-settings-unarchive-sessions` 提供
（注册 `settings.section`，id `archived-sessions`），能力只有搜索 + 取消归档。同一份归档集还需要删除
（`@morlay/session-rdb` 已提供 `POST /api/session.delete`，只限已归档）与导入
（`POST /api/session.import`）；上游那页没有这两个动作，而本仓库此前把导入挂在会话头部
（`conversation.session.header.utilities`，语义是**覆盖当前会话内容**），与「管理归档集」不同源。

**决定**

禁用上游 `ui-settings-unarchive-sessions` 行，由自有的「对话管理」页
（`@morlay/ui-conversation-manager`，`sidebar.panellist` + `main` keyed 成对注册）承载归档集的全部操作；
导入改为**新建会话**（不带 `sessionId`），会话头部那条覆盖式导入入口随之移除。

**考虑过的选项**

- 扩展上游设置页：上游 `@deepseek-ai/*` 只读，改不了。
- 设置页与新页面并存：同一份归档集两个入口，删除/导入只在其一，用户要先知道该去哪一页。
- 保留头部的覆盖式导入：覆盖需要一个「当前会话」目标，管理页没有这个上下文，且它与取消归档/删除不同源。
- 删除放开到未归档会话：与 [ADR-会话删除仅限已归档且硬删](../../session-rdb/.agents/adrs/20260917-会话删除仅限已归档且硬删.md)
  冲突；未归档会话可以先在工作区归档、再到本页删除。

**后果**

- 归档集只有一个入口：搜到的行即可取消归档、删除，或按 zip 导入成新会话。
- 上游设置页不再出现「已归档会话」；回退要改装配（重新启用该行）。
- 覆盖式导入不再可用：zip 只能落成新会话。要在已有会话上覆盖内容需另立入口，当前没有这个需求。
