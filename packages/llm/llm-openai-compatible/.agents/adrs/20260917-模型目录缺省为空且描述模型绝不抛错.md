# 模型目录缺省为空且描述模型绝不抛错

状态：已采纳

`models` 缺省 = 服务**空目录**：`listModels` 返回空，未列出的 id 原样透传
（`resolveModel` 返回基础信息 + `defaultContextWindow` / `defaultMaxTokens`）。
模型 `maxTokens` 配置后成为该模型的 per-request 默认输出上限；
`inputModalities` 缺省 `[text]`，声明含 `image` 的模型接受图片输入。

模型声明 `reasoningEfforts`（对象）后选器公开 `efforts`（按声明顺序）+
`defaultEffort`（= `profile.reasoning`，须在模型能力内，否则视为无默认值）；
不声明（或 `false`）→ 不公开 reasoning 能力。**描述模型时绝不抛错**：请求级
`options.reasoningEffort` 不在模型能力内时，在网络 I/O 前抛
`LlmError('UNSUPPORTED_REASONING_EFFORT')`；`profile.reasoning` 配了模型不支持的
档位则在同一请求执行处失败，配置页面仍可编辑。

## 考虑过的选项

- **模型 discovery**（端点询问 `GET /models`）：暂缓（YAGNI）——需要时
  手写 `models`。
- **描述模型时抛错**（配置了模型不支持的档位）：配置页面无法编辑——错误
  推迟到请求执行处（同一错误码），配置仍可保存。
- **`modelOverrides` 覆盖层**：providers 里每个路由自己写 `models` 即可，
  多一层覆盖徒增解析顺序。
- **OAuth / 非 bearer 认证**：暂缓（YAGNI）——需要时另立方案。

## 后果

- 未列出的模型 id 原样透传（空目录下任何 id 都可用，能力信息用默认值）；
  `profile.reasoning` 配了不支持的档位 → 请求执行处失败，配置页面仍可编辑。
