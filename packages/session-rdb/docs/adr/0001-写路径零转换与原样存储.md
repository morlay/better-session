# 0004-写路径零转换与原样存储

rdb 持久化采用**原样存储**：事件原样落库（与上游 JSONL 写路径一致，无过滤
无重编号），事件 seq 即稠密 seq（连续递增、无空洞）；事件内容、surfaceOp
**原样落库**（写路径零转换），`f_data` 存完整事件（含 ignorable 信封，与
JSONL 每行同构）。写路径 v2 校验（`validateStoredEvents`）只拒绝未知类型
（非 ignorable）与非法消息形状，不做坐标转换。

## 考虑过的选项

- **瞬时事件过滤 + 稠密重编号**（旧实现）：`assistant/chunk` 与 ignorable
  事件不入库、幸存事件压缩重编号，读取时经 `f_original_seq` 映射重映射
  replace range / shadowedRange——与上游 JSONL 语义不一致（上游无过滤），
  且 `assistant/chunk` 在 0.1.3 已删除（原样落库会被 fail-closed 拒绝）。
- **按上游 seq 原样落库（含空洞）**：读取视图与上游一致，但
  `ctx.sessions.create` 的 contiguous-from-0 校验会拒绝带空洞的 seed。

## 后果

- 读取路径无坐标映射（原样存储恒等）；replace 的 provenance 读取时重计算
  （优先权威 shadowedSeqs，回退 range 扫描）。
- fork 派生会话因前缀重编号后与父稠密坐标数值相同，无需额外坐标重映射。
- 上游 seq 与稠密 seq 恒等——写读对齐的关键不变量。
