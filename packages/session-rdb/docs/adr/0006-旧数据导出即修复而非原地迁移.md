# 0006-旧数据导出即修复而非原地迁移

旧格式数据（v1 表结构或 v2 表结构下的旧数据格式、surface 语义损坏）的
修复**并入导出路径**（`readRaw`）：读取时按旧格式解析（`rowToEvent` 兼容
纯 data 形状），序列化前对内存事件列表应用容错修复（`repairSurfaceOps`：
非法 replace 降级为 append、缺 surfaceOp 补标记、非 surface-eligible 清掉）、
重算 provenance、收缩继承前缀长度，产出**完备可用**的 JSONL artifact。
修复只作用于导出视图，**不落库**——写路径零转换不变量不变。

## 考虑过的选项

- **原地修复数据行**：破坏「写路径零转换」不变量，且修复逻辑与写路径
  耦合；历史加载失败的会话无法修复。
- **单独修复脚本**：需要维护与导出路径重复的解析逻辑，且用户必须知道
  何时运行。

## 后果

- 表结构级破坏性变更走 drizzle-kit 生成的迁移（`drizzle/` 目录，运行时
  drizzle `migrate()` 执行，`SCHEMA_VERSION` 门禁）；导出即修复只处理同版本
  内的数据格式差异。
- 历史加载失败的会话仍可正常导出，导出的 zip 导入后即为可用的新会话。
