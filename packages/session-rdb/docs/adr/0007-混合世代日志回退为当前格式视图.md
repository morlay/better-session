# 0007-混合世代 log 回退为当前格式视图

旧写入器只在建会话时落一次 `f_version`，之后跟随上游演进继续向同一个 log
追加事件——log 因此可能是混合世代（v0 时代的行 + 新版本字段），不是任何单一
已发布格式。`readLog` 对 `f_version < SESSION_FORMAT_VERSION` 的会话先走上游
迁移链，迁移链拒绝时**回退**为当前格式视图（实现步骤见
[legacy-clean.md](../legacy-clean.md)）。

## 考虑过的选项

- **只保留严格迁移链**：混合世代 log 永远加载失败（用户报错「过不了新版本
  验证」），只能导出再导入；导出本身也走 readLog，同样失败。
- **放弃迁移链、统一按当前格式读取**：真正的旧格式数据（`assistant/chunk`、
  旧消息形状）会丢失迁移语义；迁移链仍是这些数据的正确路径。
- **原地改写数据行**：破坏「写路径零转换」不变量，且与读取视图修复重复。

## 后果

- 回退不放松 fail-loud：旧事件类型仍由 `validateStoredEvents` 拒绝，已提交区
  的 seq gap / 不可解析行仍由 `scanRows` 拒绝；回退只是把「可迁移」判定的
  失败降级为「按当前格式解释」。
- 读取视图修复（形状补全与坐标修复）见 [read-path.md](../read-path.md)。
- 回退只作用于内存视图，不落库；下一次写入仍以原样存储追加。
- 迁移链会生成/合并事件，其读坐标与存储 head 不一致；`open(id, "write")`
  检测到该差异时把迁移视图整体落库（`rewriteMigratedLog`），使读写同坐标
  （见 [legacy-clean.md](../legacy-clean.md)）。
