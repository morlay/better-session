# 0005-事件实体全局化与桥接行承载会话专属信息

存储模型把事件拆成两层：`t_events` 是**全局事件实体**（`f_data` 存完整
原始 data，不含任何 session 专属信息），`t_session_events` 是**会话桥接行**
（稠密 seq、上游 seq、surface 元数据 `surfaceOp` 全部在桥接行上）。一个
事件行可被多个会话的桥接行引用——fork 派生会话复用父会话事件行，**不复制
事件行**，只插入新桥接行（新 `f_sequence` + `f_original_seq`）。

## 考虑过的选项

- **事件行按会话复制**（每会话一份完整事件）：实现简单，但 fork 派生
  大量会话时存储膨胀，且同一事件的多个副本难以保证一致。
- **事件行内嵌会话信息**：一个事件被多会话引用时无法表达（需要复制或
  多值列）。

## 后果

- 写路径需处理「事件行已存在则复用、否则新建」（`INSERT OR IGNORE` 语义）。
- rewind / 会话删除后产生孤儿事件行，需惰性 GC（`NOT IN` 清理）。
- 事件 id 关联与重建可行性分析见 `docs/event-reconstruction.md`。
