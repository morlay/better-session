# 0004-写路径零转换与稠密坐标重编号

rdb 持久化采用**单一稠密坐标**：瞬时事件（`assistant/chunk` 与 ignorable
事件）不入库，幸存事件按持久化计数压缩重编号（连续递增、无空洞）；事件
内容、surfaceOp、shadowedRange **原样落库**（写路径零转换），坐标转换
集中在读取路径——`f_original_seq` 记录上游 seq（含瞬时事件计数），读取时
构建 `f_original_seq → f_sequence` 映射把 replace range / shadowedRange
从上游坐标重映射到稠密坐标。映射是存储事实，无启发式。

## 考虑过的选项

- **按上游 seq 原样落库（含空洞）**：读取视图与上游一致、无需重映射，但
  `ctx.sessions.create` 的 contiguous-from-0 校验会拒绝带空洞的 seed，且
  rewind 截断后空洞语义难以维护。
- **读取时启发式猜测坐标**：无存储事实可查，崩溃 / 截断后不可靠。

## 后果

- 读取路径承担全部坐标转换复杂度（映射构建、replace range 重映射、
  provenance 重计算）。
- fork 派生会话因前缀重编号后与父稠密坐标数值相同，无需额外坐标重映射。
- 上游 cursor 与稠密 head 在 load / adopt 重建 seed 后恒等——写读对齐的
  关键不变量。
