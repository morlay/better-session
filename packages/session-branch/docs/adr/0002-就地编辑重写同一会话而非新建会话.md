# 0002-就地编辑重写同一会话而非新建会话

edit / retry / reroll 采用**就地编辑**语义：rewind 截断到目标轮之前的闭合
`turn/end` 边界，再 append 版本效果与重放输入回**同一会话**（session id
不变、版本树保持单根）；只有 fork 才派生新 id。这是产品语义对齐
[dsh-message-edit](https://github.com/Moeblack/dsh-message-edit) 的决策——
用户期望「编辑这条消息」而不是「开一个新会话」。

## 考虑过的选项

- **每次编辑派生新会话**：实现更简单（纯 append），但会话 id 变化会破坏
  客户端窗口、引用与用户心智模型，与产品语义不符。

## 后果

- rewind 必须支持 live 会话（截断 RDB 与内存 log、同步 coordinator cursor、
  重置 agent 轮次游标），是 rdb 实现中最复杂的路径。
- 版本树因此出现「同 id 多版本」形态：timeline 节点以 `parentSession` +
  `seedLength` 血统投影，根为原始会话。
