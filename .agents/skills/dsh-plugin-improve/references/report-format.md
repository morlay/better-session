# 报告格式

临时产物：写到仓库约定的临时产物目录 `.scratch/`（`.gitignore` 里忽略，不进仓库），文件名带时间戳，
**不输出 HTML**。

## 骨架

开头三行：`# 架构评审 — <项目>`、日期、一行图例
（`[模块]` = 模块，`- - ->` = 接缝，`-->` = 调用 / 依赖，`==>` = 泄漏）。

每个候选用一个二级标题小节，按这个顺序：

1. **标题**——命名深化了什么（「折叠 X 的管道」），不是「重构 X」。
2. **元数据行**——推荐强度 `Strong` | `Worth exploring` | `Speculative`；涉及的文件（等宽列出）。
3. **问题**——一句话，哪里疼。
4. **方案**——一句话，改变什么；不写接口。
5. **前后**——两个图（之前 / 之后），mermaid 或 ASCII。
6. **收益**——要点，每条 ≤6 字，用术语命名。
7. **与 ADR 冲突**——仅当值得重开时才写，引用块标注：
   `⚠️ 与 ADR-NNNN 矛盾——但值得重开因为…`。

报告最后是「首选推荐」：水平分隔线 + 三级标题 + 候选名与一句话理由。

## 规矩

- **图表承载重量**：散文一句就够；图需要配段落说明，就重画图。
- **收益用术语命名**：局部性、杠杆效应、接口缩小、实现吸收包装器；不写「更易维护」「更干净」。
- 术语精确：模块、接口、实现、深度、浅层、接缝、适配器、杠杆效应、局部性（见 `dsh-plugin-design`）；
  领域名用 `.agents/CONTEXT.md` 的词，上游名用上游真源的词。
- 有节制用符号：`⚠️` 警告、`✅` 正面、`❌` 负面。
- 报告其余部分是纯 Markdown。

## 图型（按需挑）

- 依赖 / 调用流 → mermaid `flowchart LR`；「之前 6 次往返、之后 1 次」→ `sequenceDiagram`。
- 分层浅层性 → 剖面图：之前堆 6 个薄条带，之后合并成 1 个厚条带并标注合并后的职责。
- 调用树折叠 → 之前嵌套列表列出每个内部调用，之后一个条目、内部调用写成括注。
