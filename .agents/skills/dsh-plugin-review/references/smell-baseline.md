# 坏味道基线

固定的启发式清单，仓库没有任何文档时也适用。两条纪律：

- **仓库规范优先**：已记录的规范认可的东西，抑制该条。
- **始终是判断**：每条都是带标签的启发式（「可能是特性依恋」），不是硬性违规；工具已强制的（oxfmt 格式、
  oxlint / type-aware 类型检查）不再重复报。

## 本仓库专属

每条按「征兆 → 判据」对照差异：

- **浅层模块 / 透传**——征兆：一个模块的接口几乎和实现一样复杂，或者大多只是把调用转给上游服务。
  判据：删掉它，复杂度是消失，还是在 N 个调用点重新出现；本仓库里「薄薄包一层上游服务再注册」的插件
  尤其要看它是否只做转发（那应该被吸收进真正的调用方，见 `dsh-plugin-design` 的深度判据）。
- **实现耦合测试**——征兆：测试 mock 内部协作者、直接读库表 / 私有字段、import 包内部路径。
  判据：行为没变而重构让测试碎掉；改动所属层的 `.agents/standards/` 里没有这个测试落点。
- **同义反复断言**——征兆：期望值由被测代码同一种方式算出来（用实现导出的常量当字面量、手工复刻的
  实现推导出的快照）。判据：把实现的算法换一种写法，测试还会不会红；不会红就是同义反复。
- **越过接缝测试**——征兆：跨包消费不走包出口（含各包的 `testing` 出口），装配面手搓插件列表而绕过
  `cordis.patch.yml` 的声明。判据：改动所属层 standards 里这个行为该由哪一面守护——测试不在那一面就是错位。
- **复制上游代码未登记债**——征兆：fork 或照抄上游实现进了本仓库，动机、差异与回退条件没有落 home。
  判据：这类整包 fork 与新增的复制段必须有同层 `.agents/debts/` 的登记（动机、差异、升级时怎么看、
  Done when）；没有登记就是债没入账。
- **上游知识只写在适配层之外**——征兆：上游字符串标识 / 私有字段名漏进消费侧，或按发布包的 d.ts 猜语义。
  判据：上游细节是否只存在于适配层与 vendor 真源引用里。

## 通用清单（Fowler《重构》第 3 章）

- **神秘命名**——名字说不清它做什么或装什么 → 重命名；找不到诚实的名字，说明设计本身含混。
- **重复代码**——同一逻辑形态出现在多个 hunk 或多个文件 → 提取共享形态，两处都调用它。
- **特性依恋**——方法访问另一个对象的数据多于自己的 → 把方法移到它依恋的数据上。
- **数据泥团**——同一组字段或参数总是结伴出现（一个待诞生的类型）→ 打包成一个类型，传递那个类型。
- **原始类型迷恋**——用原始类型或字符串代表本该有自己类型的领域概念 → 给该概念一个小类型
  （跨边界 id 用 branded 类型，见 `.agents/standards/`）。
- **重复的 switch**——对同一判别值的 `switch`/`if` 级联在变更中反复出现 → 用多态替换，或两处共享一张
  映射表。
- **霰弹式修改**——一个逻辑变更迫使修改散布在许多文件 → 把一起变化的东西收拢进一个模块。
- **发散式变化**——一个文件因多种不相关原因被修改 → 拆分，使每个模块只为一种原因而变化。
- **投机性泛化**——为规格没有的需求添加抽象、参数或钩子 → 删除，内联回去，直到出现真实需求。
- **消息链**——调用方本不该依赖的长 `a.b().c().d()` 导航 → 把遍历藏进第一个对象的一个方法后面。
- **中间人**——大多只是继续转发的类或函数 → 砍掉，直接调用真正的目标。
- **被拒的遗产**——子类或实现者忽略、覆盖了它继承的大部分内容 → 去掉继承，改用组合。
