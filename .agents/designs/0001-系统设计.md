# 0001 系统设计

状态：**已实现**（四层服务 + 装配 bundle 已落地，示例工作区的 web 与 desktop 两种模式可跑）
范围：本仓库全部包的职责、分层、装配与操作语义——各包内部实现细节在包层 `.agents/`；上游同步 / 适配流程在
`.agents/skills/`。
约束：**不改上游、不改 vendor**（`@deepseek-ai/*` 与 `vendor/**` 只读，扩展只走 cordis 插件层与本地 patch）。

分支式会话编辑：在不修改上游 `@deepseek-ai/*` 代码的前提下，为 DeepSeek Harness
会话提供 **就地编辑 / 重试 / 撤回 / 分支**（rewind / retry / recall / fork）闭环——GUI
里撤回用户消息到输入框或就地重写、重试任意回合，重写**同一会话**（session id
不变），只有分支才派生新 id。领域术语与全部包的上下文归属见
[`CONTEXT-MAP.md`](../CONTEXT-MAP.md)。

## 结论摘要

| 议题                   | 结论                                                                                                                                                                                                                                                                                                                                       | 一句话理由                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 分支面                 | `SessionBranchProvider` 是与上游 `SessionHandle` **平行**的额外 provider 抽象，rdb 同时实现两者并自动注册 `ctx.sessionBranch`（[ADR-0001](../../packages/session/session-branch/.agents/adrs/0001-分支面作为与上游SessionHandle平行的provider抽象.md)）                                                                                    | append-only 与「显式回退 + 闭合边界派生」是两种写入语义，分开后上游不必改 |
| 就地编辑               | edit / retry / reroll 用 `rewind` 截断 + `append` 重写**同一会话**，session id 不变、版本树单根；只有 `fork` 创建新 id（[ADR-0001](../../packages/session/ui-conversation-message-actions/.agents/adrs/0001-就地编辑重写同一会话而非新建会话.md)）                                                                                         | 会话身份不变，历史才可追溯                                                |
| 撤回（recall）         | 只 `rewind` 截断到目标消息边界（轮首到前一轮 `turn/end`，轮内 followup 与轮外 user 消息 exclusive drop），不重写、不重放、不写版本效果，文本由 client 回填 composer（[ADR-0004](../../packages/session/ui-conversation-message-actions/.agents/adrs/0004-编辑入口不依赖轮次归属.md)）                                                      | 用户要「改完自己发」，重放等于代替用户决定                                |
| rewind 支持 live 会话  | 截断 RDB 与内存 log、对齐 handle cursor、重置 agent 轮次游标；截断前先停止运行中的 loop（`cancel` + `whenIdle`）（[ADR-0003](../../packages/session/session-rdb/.agents/adrs/0003-rewind绕过handle模型直接截断.md)、[ADR-0005](../../packages/session/ui-conversation-message-actions/.agents/adrs/0005-rewind前主动停止运行中的loop.md)） | GUI 打开中的会话也要能就地编辑，且不能与 agent 写内存 log 并发            |
| ignorable 版本效果     | 分支版本事件原样落库（带 `ignorable` 信封），非 branch 读者安全跳过（[ADR-0002](../../packages/session/session-branch/.agents/adrs/0002-版本效果以ignorable事件原样落库.md)）                                                                                                                                                              | 写路径零转换；是否参与投影由读侧凭信封决定                                |
| 配置覆盖               | `$DSH_HOME/settings.yaml` 的 `session-rdb` namespace 覆盖 cordis 层 entry config（注册于 `ctx.settings`）（[ADR-0002](../../packages/session/better-session/.agents/adrs/0002-配置经settings服务覆盖而非直接改cordis配置.md)）                                                                                                             | 运行期可改，不必重装 patch                                                |
| 原地重写日志的派生水位 | 截断后主动失效 `ctx.tokenMeter` 折叠与投影单元缓存（能力探测 + 告警），并用 `balanceRewindPrefix` 配平保留前缀（[债务 0003](../debts/0003-token-meter水位按位置前进需主动失效.md)）                                                                                                                                                        | 上游水位按位置前进而非事件身份，不失效就会在错位处继续折叠                |

### 分层模型

三层 cordis plugin，依赖单向向下：

```
契约层  @morlay/session-branch                provider 抽象 + 版本树投影
   ▲        ▲
   │        │
编排层  @morlay/ui-conversation-message-actions   SessionEditor 编排 + client UI（conversation.chat.node 替换）
   │        │
实现层  @morlay/session-rdb                  RDB 持久化 + branch provider 双服务
```

| 层     | 包                                        | 职责                                                                                                                                             |
| ------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 契约层 | `@morlay/session-branch`                  | `SessionBranchProvider` 抽象（rewind / forkFrom / readBranchPrefix）+ `SessionBranch` 服务 + `buildTimeline` 版本树投影                          |
| 编排层 | `@morlay/ui-conversation-message-actions` | `SessionEditor` 编排（edit / retry / recall / fork 完整功能）+ client bundle（`conversation.chat.node` 渲染替换）                                |
| 实现层 | `@morlay/session-rdb`                     | RDB 持久化（实现上游 `SessionHandle` 模型）+ 分支 provider（实现 `SessionBranchProvider`）+ storages 接管（投影缓存服务与 workspace 域 KV 后端） |
| 聚合   | `@morlay/better-session`                  | profile bundle：`cordis.patch.yml` 一次性装配以上全部到 web profile                                                                              |

client 半（浏览器）除编排层自己的 bundle 外，还依赖本仓库的对话 UI 接管包与样式基础
（`session/ui-conversation`、`session/ui-chat`、`session/ui-input-trigger`、
`client/ui-primitives`）——接管动机、差异登记与回退条件见
[债务 0001](../debts/0001-临时接管上游对话UI的client半.md)。

## 装配（`@morlay/better-session` bundle patch）

`cordis.patch.yml` 一次装配四层服务：持久化（RDB，替换官方 jsonl）、分支
数据、edit / retry / recall / fork 编排、`conversation.chat.node` 渲染替换，并把
对话 UI 的三个官方行换成 fork 行。装配链与服务调用示例见
[packages/session/better-session/README.md](../../packages/session/better-session/README.md)，
rdb 替换的起因与权衡见
[ADR-0001](../../packages/session/better-session/.agents/adrs/0001-rdb替换官方jsonl持久化.md)。

默认配置为 SQLite（`$DSH_HOME/sessions/sessions.sqlite`）；`session-rdb`
namespace 可覆盖为 PostgreSQL（`connectionString`）；官方
`session-persistence-jsonl` 被禁用（`disabled: true`）。

**storages 一并接管**：官方 `storage-json` 与 `session-projection-cache` 同被
禁用，`storage-domain` 的 backend 路由为 session-rdb 注册的 `rdb` 后端——
workspace 域经上游 `StorageBackend.kv` 契约落 `t_workspaces` /
`t_workspace_state`，投影 checkpoint 由 session-rdb 提供的同名
`ctx.sessionProjectionCache` 服务落 `t_session_projcache` /
`t_session_projcache_row`；`$DSH_HOME/storages` 不再产生文件
（[ADR-0009](../../packages/session/session-rdb/.agents/adrs/0009-接管storages到rdb语义表.md)）。

**会话查询服务一并接管**：官方 `session-query-sqlite`（FTS5 派生索引库）禁用，
由 session-rdb 提供同名 `ctx.sessionQuery`——精确读 / 过滤 / 血缘复用上游
`SessionQueryEngine` 基类（数据面走 `ctx.sessionPersistence`），全文检索维持
disabled，不引入派生库
（[ADR-0010](../../packages/session/session-rdb/.agents/adrs/0010-接管会话查询服务所有权.md)）。

装配面由 `packages/session/better-session/src/__tests__/assembly.spec.ts` 守护：
patch 里的每个 insert 行都必须能在工作区内解析到真实包、且是本 bundle 的依赖
（反之依赖也不得漏装配），fork 的 client 包必须声明 client-modules 需要的入口与平台。

## 操作语义

`edit` / `retry` / `reroll` 就地重写同一会话（`rewind` 截断 + `append`
重放，session id 不变）；`recall` 只 `rewind` 截断并把消息文本交回 composer
（不重放）；只有 `fork` 派生新 id。落在被截断区间里的**完整压缩事务会在重写时补回**
（重排为 standalone 形态，保证摘要仍生效、压缩仍可再触发，见
[编排层 ADR 0008](../../packages/session/ui-conversation-message-actions/.agents/adrs/0008-压缩事务在重写时补回.md)）。
各操作的完整语义见
[packages/session/ui-conversation-message-actions/README.md](../../packages/session/ui-conversation-message-actions/README.md)。

## 可配置沙箱（packages/sandbox/dsh-sandbox-local）

`@morlay/dsh-sandbox-local` 替换官方进程沙箱与文件系统围栏：`access` 的
`rw <path>` 条目追加工作区与平台临时目录之外的可写根（支持 `{{ env.NAME }}` 模板），
`r- <path>` 条目只读（读放行、写拒绝），`-- <pattern>` 条目拒绝访问（读 + 写，
支持相对会话工作区的 glob）。进程沙箱侧继承官方
`LocalSandboxProvider` 并在 `confine` 结果上追加规则——Seatbelt 完整生效
（后置 SBPL 规则覆盖官方先置的 allow，真实 `sandbox-exec` 已验证），bwrap
退化为只读、Landlock 与 Windows ACL 无表达，加载期告警；fs 侧继承官方
`LocalFileSystem` 自实现围栏，使 read / write / edit 工具在所有平台语义一致。
配置、语法与限制见
[packages/sandbox/dsh-sandbox-local/README.md](../../packages/sandbox/dsh-sandbox-local/README.md)，
取舍见
[ADR-0001](../../packages/sandbox/dsh-sandbox-local/.agents/adrs/0001-替换官方进程沙箱与fs围栏以支持额外可写根与拒绝项.md)。

## 桌面化（packages/desktop/dsh-desktopify）

`@morlay/dsh-desktopify` 把任意工作区打包 / 运行为桌面应用：Electron 壳
（`dsh-app://` 协议 + 上游 `dsh-desktop-host` 字节管道后端），`dev` 链接
工作区直接跑，`bundle` 产出静态、无签名的应用目录。工具形态（全 TS、
exports 收敛）、运行流程与运行时语义见
[packages/desktop/dsh-desktopify/README.md](../../packages/desktop/dsh-desktopify/README.md)，
路线取舍见 [ADR-0003](../adrs/0003-桌面化从golang壳迁移到Electron与上游desktop-host.md)。

## 取舍

被否掉的路线（理由的 home 是各自的 ADR / 债务，这里只列结论）：

- **替换上游 `SessionHandle`**、而不是平行加分支面：rdb 会被 coordinator 私有实现绑住
  （[ADR-0001](../../packages/session/session-branch/.agents/adrs/0001-分支面作为与上游SessionHandle平行的provider抽象.md)）。
- **保留官方 JSONL 持久化**、只在上面旁路截断：顺序介质给不了原子截断
  （[ADR-0001](../../packages/session/better-session/.agents/adrs/0001-rdb替换官方jsonl持久化.md)）。
- **只用 slot 注入改上游对话 UI**、不 fork：插件面只有整格 shadow keyed slot，无组件级 wrap
  （[债务 0001](../debts/0001-临时接管上游对话UI的client半.md)）。
- **为桌面化另写宿主与启动逻辑**、不复用上游：会产生第二套后端启动路径
  （[ADR-0003](../adrs/0003-桌面化从golang壳迁移到Electron与上游desktop-host.md)）。

## 开放问题

还没定的事，各自的 home 是债与包层设计：

- 上游是否提供 meter 失效 / 回退 API，决定我们侧的 duck-type 失效能否删（[债务 0003](../debts/0003-token-meter水位按位置前进需主动失效.md)）；
- 对话 UI fork 的三项上游能力何时具备，决定逐项回退的时机（[债务 0001](../debts/0001-临时接管上游对话UI的client半.md)）；
- client 侧测试 harness 的来源（上游 test runtime 或自建），决定 slot 装配面何时有测试（[债务 0002](../debts/0002-对话UI客户端半的装配面缺测试辅助.md)）。
